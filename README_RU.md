# fix_fb2_metadata.py

Утилита на Python для поиска и преобразования числовых XML-ссылок на символы в разделе `<description>` файлов электронных книг FB2.

Скрипт предназначен для библиотек, в метаданных которых встречаются записи вида `&#1046;` или `&#x416;` вместо соответствующих символов Unicode.

## Что делает скрипт

- Рекурсивно ищет файлы с расширением `.fb2` без учёта регистра.
- Преобразует десятичные и шестнадцатеричные числовые XML-ссылки внутри `<description>...</description>` в символы Unicode.
- Распознаёт также двойной вариант экранирования `&amp;#...;`.
- Определяет кодировку из XML-декларации. Если декларации с кодировкой нет, используется UTF-8.
- Записывает изменённые файлы в UTF-8 и обновляет существующий атрибут `encoding` в XML-декларации на `utf-8`.
- Перед изменением создаёт резервную копию, сохраняя относительную структуру каталогов.
- Продолжает обработку после ошибок отдельных файлов и записывает подробности в журнал рядом со скриптом.
- При ошибке декодирования пытается определить тип файла. Для ZIP может указать имя вложенного файла `.fb2`, если он найден. Архивы не распаковываются и не изменяются.

## Требования

- Рекомендуется Python 3.9 или новее.
- Сторонние Python-пакеты не требуются.

## Краткая инструкция

Сначала запусти проверку без изменений. Это режим по умолчанию:

```bash
python3 fix_fb2_metadata.py "/путь/к/библиотеке"
```

Явный режим проверки:

```bash
python3 fix_fb2_metadata.py "/путь/к/библиотеке" --dry-run
```

Применить исправления:

```bash
python3 fix_fb2_metadata.py "/путь/к/библиотеке" --apply
```

Перед запуском с `--apply` проверь вывод режима `dry-run`. Параметры `--apply` и `--dry-run` взаимоисключающие.

## Резервные копии и журнал ошибок

При запуске с `--apply` резервные копии создаются в каталоге `_fb2_backup/` внутри корневого каталога библиотеки. Структура каталогов относительно корня сохраняется. Существующие резервные копии не перезаписываются: если целевой файл уже существует, для соответствующей книги будет зарегистрирована ошибка, а исходный файл не изменится.

Журнал называется `fix_fb2_metadata_errors.log` и создаётся рядом со скриптом. В нём сохраняются время, путь к файлу, причина ошибки и описание типа файла при ошибке декодирования Unicode. Для непредвиденных исключений записывается traceback. После ошибки скрипт продолжает обработку остальных файлов.

## Что пропускается

- Каталоги с именами `_fb2_backup`, `_mp3_tag_backup` и `backup`.
- Файлы, имена которых начинаются с `._` — обычно это служебные файлы AppleDouble, создаваемые macOS.

## Ограничения

- Для поиска `<description>` используются регулярные выражения, а не полноценный XML-парсер.
- Изменяются только числовые ссылки внутри `<description>`. Ссылки в других частях FB2 не затрагиваются.
- Недопустимые кодовые точки Unicode остаются без изменений.
- Если файл не удаётся декодировать в заявленной кодировке (или в UTF-8, если кодировка не объявлена), он регистрируется как ошибка и остаётся без изменений.
- ZIP-архивы с расширением `.fb2` только распознаются и описываются в журнале; их содержимое не исправляется.
- Синтаксис Python проверялся, но полный запуск на всей библиотеке и все варианты FB2 не проверены.

## Код завершения

- `0` — обработка завершена без ошибок файлов.
- `1` — возникла ошибка при обработке одного или нескольких файлов.
- `2` — указанный каталог не существует или не является каталогом.
